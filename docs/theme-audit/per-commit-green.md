# 每笔各自绿 · 本轮成文的三条规矩

写这份是因为这三条以前只在对话里说过，翻不上账，于是同一个错犯了三次。

## 1. 断言和它断的代码必须同一笔

`796e12f` 把 `chatView` 改回 `input`，而它断的代码在 `9050531`。两笔分开，`796e12f` 单独跑第 10 步必挂。当时等于两笔一起验，不是每笔各自绿。

## 2. 上一笔绿了才推下一笔

排队被取消、下载超时不算绿——那些不是代码的判断，是机器没来。重新触发、等到真的绿再往下，界面上「success」才是门。

本轮反面样本：`de9f101` 连着六次 0 步取消（`runner_id 0`、`steps 0`、14 分 59 秒被平台收回），一次资源都没拿到。它不是失败，也不能当通过。

## 3. 报告里的数字，写之前先复跑一遍

本轮教训：断言数写 5，实际 9；笔数写 47，交上去时已经 50；「九条断言」后面跟着十条。

会随提交变的数字，要么写进文末并注明「以本次查证时刻为准」，要么干脆不写。

---

这三条同时适用于我和任何接手的代理。规矩写在仓库里，就不依赖谁记得。
